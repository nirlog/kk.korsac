# kk.korsac

Bitrix D7 module for KORSAC option directories and domain schema infrastructure. Version 0.12 adds public Passport HTTP delivery at `/passport/{PUBLIC_ID}/`, a safe Bitrix component and idempotent delivery installation/health. Version 0.11 added independent System Passport preparation/physical-handoff activation, secure one-time credentials and a privacy-safe public projection. Version 0.10 added Sale Order → physical System synchronization and a separate production status/history workflow; automation is disabled until its exact Sale trigger ID is configured. Version 0.9 added physical System persistence and concurrency-safe SYSTEM ID generation. Version 0.8 shipped the storefront-neutral headless browser core, neutral DOM configurator renderer, and the `kk:korsac.configurator` product-card bridge for the public configuration and Cart actions. Product `*_DEFAULT`, `*_OPTIONS`, and `*_MULTI_OPTIONS` properties refer to simple HL option records. The module owns schema, migrations, health checks, configuration reads, policy-based configured-product quotes in integer minor units, immutable commercial snapshots, and configured Bitrix Basket integration. Payment, delivery, inventory and final storefront design remain outside this repository.

See [`local/modules/kk.korsac/README.md`](local/modules/kk.korsac/README.md), the [v0.2 HL specification](docs/architecture/KORSAC-HL-TECHNICAL-SPEC.md), the [product property convention](docs/architecture/KORSAC-PRODUCT-CONFIGURATION.md), [configuration pricing](docs/architecture/KORSAC-CONFIGURATION-PRICING.md), [default configuration cost](docs/architecture/KORSAC-DEFAULT-CONFIGURATION-COST.md), the [public Configurator API](docs/architecture/KORSAC-CONFIGURATOR-API.md), the [frontend configurator core](docs/architecture/KORSAC-FRONTEND-CONFIGURATOR-CORE.md), the [frontend DOM renderer](docs/architecture/KORSAC-FRONTEND-CONFIGURATOR-RENDERER.md), the [product configurator component](docs/architecture/KORSAC-PRODUCT-CONFIGURATOR-COMPONENT.md), and the [Cart snapshot architecture](docs/architecture/KORSAC-CART-SNAPSHOT.md).

Pricing policies can be managed in Bitrix admin at **Services → KORSAC →
Ценообразование**. Storage semantics and CLI interoperability are documented in
the [pricing admin architecture](docs/architecture/KORSAC-PRICING-ADMIN.md).

System core is documented in [KORSAC-SYSTEM-DOMAIN.md](docs/architecture/KORSAC-SYSTEM-DOMAIN.md). It provides explicit idempotent creation for one physical ordered PC unit, an existing snapshot reference and actual installed-component history storage. Warranty duration/claims, service workflow, ownership, inquiries and System Admin UI remain future stages. Sale synchronization and production status/history are implemented in v0.10, Passport backend and handoff-based warranty start in v0.11. KORSAC uses its own standalone Bitrix installation/database; no King-Komp runtime integration is introduced.

The [Sale/System automation architecture](docs/architecture/KORSAC-SYSTEM-SALE-AUTOMATION.md) covers migration 007, backend settings, manual CLI, retry/conflict rules, status labels and the required live Bitrix/Sale deployment gate.

Passport Core v1 is specified in [KORSAC-SYSTEM-PASSPORT.md](docs/architecture/KORSAC-SYSTEM-PASSPORT.md): PUBLIC_ID is opaque, SECRET_CODE is issued once with only SHA-256 persisted, and physical transfer starts warranty. HTTP delivery at `/passport/{PUBLIC_ID}/` is implemented separately in v0.12; see [KORSAC-PUBLIC-PASSPORT-DELIVERY.md](docs/architecture/KORSAC-PUBLIC-PASSPORT-DELIVERY.md). Ownership, QR images and warranty duration remain future work.
