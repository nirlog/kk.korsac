# KORSAC pricing policy v1

## Price semantics

`UF_PRICE` is a raw server-side value with group-specific meaning. For CPU,
GPU, MB, RAM, SSD, HDD, PSU, COOLER and CASE it is procurement cost. For OS,
SOFTWARE and SERVICE it is already a direct-retail contribution. The single
authoritative classification is `OptionPricingModeRegistry`.

`HlOptionPriceProvider` remains the raw decimal-to-minor-unit boundary.
`RetailOptionPriceProvider` applies the configured hardware markup and passes
direct-retail groups through unchanged. Markup uses integer ROUND_HALF_UP.
`ConfigurationPriceCalculator` remains policy-agnostic and therefore computes
selected-retail minus default-retail when given the retail provider.

`DefaultConfigurationCostCalculator` remains a component-cost calculator whose
semantics depend on its explicitly supplied provider. `DefaultCatalogPriceCalculator`
sums retail prices of non-null single defaults and adds the fixed system
adjustment exactly once. Multiple SOFTWARE/SERVICE choices are excluded. The
fixed adjustment is never part of option deltas.

## Channels and Catalog price types

RETAIL is the storefront channel today; BUSINESS is reserved for a future
server-side mapping. The browser cannot select channel, price type, markup or
policy. Configurator always resolves RETAIL, then reads the policy keyed by
iblock ID and resolved price-type ID.

Bitrix module Options use deterministic keys:

* `pricing_price_type_<IBLOCK_ID>_<CHANNEL>`;
* `pricing_policy_<IBLOCK_ID>_<PRICE_TYPE_ID>` (JSON policy value).

Missing mappings and policies fail explicitly. There is no fallback to price
type 1 and **Bitrix `BASE=Y` is not a KORSAC price-selection rule**. A configured
`BASE=N` type is valid because runtime price lookup filters only by product ID
and the explicitly resolved Catalog price-type ID.

The public field `basePriceMinor` means the Catalog price of the DEFAULT
configuration for that resolved KORSAC price type; it does not mean Bitrix's
BASE price type. Only RUB is supported in v1.

## Operations

```bash
php local/modules/kk.korsac/tools/pricing.php configure \
  --iblock=2 --channel=RETAIL --price-type=1 \
  --markup-bps=2000 --fixed-adjustment-minor=0

php local/modules/kk.korsac/tools/pricing.php show \
  --iblock=2 --channel=RETAIL

php local/modules/kk.korsac/tests/Integration/pricing_policy_smoke.php \
  --iblock=2 --product=4 --channel=RETAIL
```

The configuration command writes only `kk.korsac` module Options. Neither CLI
nor calculators write Catalog or HL prices.

## Transitional consistency warning

`kk.price-update` is intentionally unchanged in this PR. Until its follow-up
adopts `DefaultCatalogPriceCalculator` and `PricingPolicy`, an existing Catalog
product price may have been generated by the old raw-default formula while
Configurator deltas use correct retail economics. `kk.korsac` does not silently
rewrite those Catalog prices.
